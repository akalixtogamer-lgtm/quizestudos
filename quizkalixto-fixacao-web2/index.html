Classes, sessionStorage e páginas dinâmicas com JavaScript

Revisão teórica dos conceitos da AV2 — para iniciantes em JavaScript. Leia com calma: cada questão revisa uma peça do sistema de login e menu que construímos.

Parte 1 · Múltipla escolha — Classes e Orientação a Objetos

Marque a única alternativa correta em cada questão.

1) Em JavaScript, uma classe funciona como:
  1. Uma variável que só aceita números.
  2. Um "molde" (modelo) que descreve os atributos e métodos que os objetos criados a partir dela terão.
  3. Uma função que só pode ser chamada uma vez.
  4. Um arquivo HTML especial.
2) Observe o trecho abaixo: 
class Produto {
  #preco;
  constructor(preco) {
    this.#preco = preco;
  }
}
O símbolo # antes de preco indica que o atributo é:
  1. Numérico.
  2. Obrigatório.
  3. Privado — só pode ser lido ou alterado por código de dentro da própria classe.
  4. Um comentário.
3) O que acontece se tentarmos executar console.log(produto.#preco) fora da classe?
  1. Imprime o valor normalmente.
  2. Imprime undefined.
  3. Ocorre um erro de sintaxe, pois atributos privados não são acessíveis de fora da classe.
  4. O navegador pede permissão ao usuário.
4) Se um atributo é privado, qual é a forma correta de permitir que outras partes do programa leiam o seu valor?
  1. Remover o símbolo #.
  2. Criar um get (getter) público dentro da classe que devolve o valor.
  3. Usar alert().
  4. Não existe forma: o valor fica perdido.
5) O constructor de uma classe é executado:
  1. Toda vez que a página é recarregada.
  2. Somente quando chamamos o método iniciar().
  3. Automaticamente, no momento em que criamos um objeto com new.
  4. Apenas quando há erro no código.

Parte 2 · Verdadeiro ou Falso — sessionStorage e JSON

Escreva V ou F na linha ao lado de cada afirmação. Cuidado: as falsas escondem erros comuns de iniciante!

(     ) 6) O sessionStorage guarda os dados apenas enquanto a aba do navegador estiver aberta; ao fechá-la, os dados são apagados.

(     ) 7) O sessionStorage consegue guardar objetos JavaScript diretamente, sem nenhuma conversão.

(     ) 8) JSON.stringify(objeto) converte um objeto em texto, e JSON.parse(texto) faz o caminho inverso.

(     ) 9) sessionStorage.removeItem("turma") apaga a chave "turma", mas o objeto sessionStorage do navegador continua existindo normalmente.

(     ) 10) Como os dados ficam salvos na sessão, um objeto criado com new em uma página continua "vivo" (com seus métodos) quando abrimos outra página.

O sessionStorage só armazena texto. Por isso, ao recuperar um objeto salvo em JSON, precisamos reconstruir a instância da classe (por exemplo, com um método estático como deJSON()) para voltar a usar seus métodos.

Parte 6 · Discursivas (respostas esperadas)

15) Com atributos privados, ninguém consegue fazer turma.vagas = -50 por fora. Toda alteração passa obrigatoriamente pelos métodos públicos, e é dentro deles que colocamos as regras de negócio — como recusar uma redução que deixaria as vagas negativas. A classe protege os próprios dados.

16) href navega guardando a página atual no histórico (o botão "voltar" funciona); replace substitui a página atual, que some do histórico. A tela de encerramento usa replace porque o enunciado exige que ela seja exibida "sem o histórico de páginas anterior" — o usuário não deve conseguir voltar ao sistema já encerrado.

17) Colocamos uma tag vazia na página, como <p id="msg"></p>. No JavaScript, localizamos o elemento com document.getElementById("msg") e escrevemos o texto com .textContent, trocando também a classe CSS para dar cor de sucesso (verde) ou erro (vermelho). Ou seja: a mensagem "nasce" dentro do próprio HTML, sem janelas do navegador.
